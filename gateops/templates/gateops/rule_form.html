Rule builder checklist

  1. Name and code: use a stable code for audit logs and support tickets.
  2. Priority: lower numbers run first. Put exceptions before generic fallback rules.
  3. Scope: blank category/gate selectors mean the rule applies to every value in that dimension.
  4. Validity: leave the end date empty for ongoing policies.
  5. Conditions/actions: after saving, add match conditions and the action to take from the rule detail page.
Avoid duplicate active rules with the same priority and broad selectors; they make operational decisions hard to audit.
